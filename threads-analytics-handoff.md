# Threads: аналитика аккаунта — передача в новый чат

Дата: 13.10.2026. Проект: платформа ai.cashruflow.ru (/home/cashruflow). Задачи в бэклоге нет (решение Константина: «без задачи»).

## Цель
Аналитика аккаунта Threads в виде 4 карточек как на скрине: «Ваши действия» (публикации), «Просмотры», «Ответы», «Новые подписчики». В каждой: число за 7 дней, «Предыдущие: N» (прошлые 7 дней, стрелка вверх/вниз), 7 столбиков по дням (последний день темнее). Тот же виджет позже поставить на страницу «Пациенты», когда платформа будет запущена.

## Решения Константина
- Отдельную страницу не делать: вкладка «Аналитика» внутри `/threads` с якорем `#аналитика`.
- Хранить историю в БД: новая таблица `threads_daily` (миграция разрешена, `CREATE TABLE IF NOT EXISTS`).
- Виджет для «Пациенты» — отдельный переиспользуемый файл.
- Пункты в roles.js / sidebar.js / page_gate не добавлять.

## Что сделано (всё на проде, правки через MCP Claude_SSE)
- `/home/cashruflow/web/threads.js`
  - таблица `threads_daily` (day PK, views, likes, replies, reposts, quotes, followers, posts, updated_at);
  - сборщик метрик: через 60 с после старта и раз в сутки (`threads_insights` по дням, `followers_count`, число постов из `/threads` за 14 дней), upsert по day; сегодня и вчера пересобираются всегда;
  - `GET /api/threads/analytics` → `{days[14], cards{posts,views,replies,followers}}` (cur, prev, series[7]); `followers` — прирост за день, текущее число в `cards.followers.now`; ленивый сбор, если последняя запись старше 6 ч; при ошибке сбора, но с данными — 200 с `collect_error`;
  - `POST /api/threads/analytics/collect` — ручной сбор;
  - ошибки Meta идут через `metaFail` (4xx с кодом, не 500);
  - сегодня текст ошибки `api_blocked` заменён на инструкцию, что делать в Meta (изменение записано на прод, **рестарт web-interface ещё не сделан после этой правки**).
- `/home/cashruflow/web/public/threads-analytics-widget.js` — `window.renderThreadsAnalytics(el, opts)`; 4 карточки на токенах `--ui-*`, 1 колонка на телефоне и 2x2 от 769px, SVG-столбики, пустое состояние с кнопкой «Собрать сейчас», плашка «нет прав на insights». Подключается `?v=1` (при правках поднимать ?v= во всех местах).
- `/home/cashruflow/web/public/threads.html` — вкладка «Аналитика» (`#аналитика`, hashchange), плашка `th-noins` вынесена под статус, добавлен `body{margin:0}`.
- `web-interface` перезапускался после основной части; ошибок кода Threads в логах нет.

## Что НЕ работает (блокер)
Цифр в карточках нет: таблица `threads_daily` пуста. Meta отвечает «API access blocked» (приложение заблокировано), в логах сборщика также «Нет прав на статистику Threads». Это не баг платформы, нужны действия в Meta for Developers. Живая проверка карточек не сделана: скрины служебного входа (claude-shot) получили 403.

## Известные ограничения
- Дни считаются по UTC, у Meta границы суток по PST — цифры могут слегка расходиться.
- `followers_count` Meta отдаёт только при 100+ подписчиках.
- «Новые подписчики» = разница ежедневных снимков; пока нет истории, показывается «—».
- Формат ответа `threads_insights` взят из документации Meta, реальный ответ код ещё не видел.
- Перезапуски web-interface частые (↺ 384→393 за сутки; их делают разные сессии): на время рестарта nginx отдаёт 502 — это не ошибка кода Threads.
- Доступ к `/threads` — гейт страниц: нужна кука `ppass` (войти на `/auth`).

## Правила платформы, важные для продолжения
- Прод правится только `write_file` / `str_replace` MCP-сервера Claude_SSE.
- Знак доллара в new_str → `String.fromCharCode(36)`; после правки HTML проверить один `</html>`, `</style>` на месте, `body{margin:0}` в каждом `<style>`.
- Подключаемые JS/CSS с `?v=` кэшируются 7 дней — поднимать `?v=` во всех местах.
- Рестарт сервисов, миграции БД, `tg_send` — только через квиз Константину.
- Цепочка: /start (днём) → /bugs (ночью) → /end (ночью, автоматически). Баги — только `create_issue`, не задачи.
