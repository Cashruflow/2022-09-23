## A. Баги, влияющие на пользователя

Это не стилистика. Сгруппировано по тяжести.

### A1. Дата результата по умолчанию считается в UTC — запись уходит во вчера

`medcard_habits.js:765`

```js
${fld('Дата', inp('hrDate','date',new Date().toISOString().slice(0,10)))}
```

`toISOString()` — UTC. Пациент в UTC+5 открывает форму в 02:00 местного 12 сентября:
по UTC ещё 11-е, и результат по умолчанию падает во вчерашний день — ломается стрик
и `met.today_fact`.

Тот же UTC-расчёт: `:618` (`today` в `schedDayHint`), `:649` («Старт — завтра, <дата>»).

Издевательство в том, что правильный хелпер лежит в этом же файле — `ymdLocal`
(`:1036`), и комментарий над ним (`:1033-1035`) описывает ровно эту ошибку
(«в поясе восточнее UTC локальная полночь по UTC — это ещё вчера»). Он на 400 строк
ниже мест, которые его не используют.

**Починка:** поднять `ymdLocal` к хелперам (~стр. 19), заменить им `:618`, `:649`, `:765`.

**Важно:** `cfToday()` из `/tz.js` сюда НЕ подходит — он считает день в поясе портала
(личная настройка в `/set`), а трекеру нужен пояс устройства пациента
(см. `medcard_habits.js:12-18`). Это не дубль, сводить нельзя.

### A2. Тост показывает московское время, карточка под ним — местное

| место | функция | пояс |
|---|---|---|
| `:871` тост «Записано: +30 в 18:00» | `tfmt` (`:11`) | `Europe/Moscow` жёстко |
| `:308` карточка «Последняя +30 · 20:00» | `tshort` (`:204-206`) | пояс устройства |
| `:1130` история «12 сент. 2026, 20:00» | `utcfmt` (`:20-24`) | пояс устройства |

Пациент в Екатеринбурге записывает в 20:00 — тост говорит 18:00, карточка под ним 20:00.
Комментарии `:12-18` и `:203` декларируют единое правило «пояс устройства»;
`tfmt` просто не обновили при переходе.

**Починка:** `tfmt` → `locHM` из `/loc-time.js` (см. C3).

### A3. Все сообщения при открытой модалке невидимы в фолбэк-режиме

`habits.html:42` задаёт `#toast{z-index:600}`, а `#habitModalBackdrop`
(`medcard_habits.js:490`) — `z-index:1100`.

Сообщения, показываемые поверх открытой модалки — `toast('Название обязательно')`
(`:695`, `:1423`), `toast(r.error)` (`:708`, `:868`), `toast('Камера насчитала: '+n')`
(`:820`) — уезжают под затемнение. `pltToast` с `z-index:9999` их показывает.

При живой сети это не проявляется (`toast.js` грузится синхронно на `habits.html:220`,
раньше `medcard_habits.js`), поэтому баг виден только в офлайн-сценарии — см. C1.

### A4. Полоса общей цели не отрисовывается никогда

`heroHtml()` (`:931`) вызывает `goalStripHtml` только для регулярных миссий:

```js
:933  if(!met.target_amount) return goalStripHtml(m);
```

А сама `goalStripHtml` (`:272`) отдаёт разметку только для накопительных:

```js
:273  const met=m.metrics||{}; if(!met.target_amount) return '';
```

Один и тот же `m`, взаимоисключающие условия → всегда `''`. Все 24 строки рендера
(`:282-297`) не исполняются ни разу.

Это **невключённая фича**, а не мусор: по комментарию `:268-269` полосу просили
30.08.2026 («цель нигде не видна цельно, только в свёрнутой карточке»), написали — и
она ни разу не показалась, потому что охранное условие на вызове инвертировано
относительно условия внутри функции.

**Решение за владельцем:** чинить вызов (показывать полосу накопительным миссиям —
судя по комментарию, задумка была такая) или удалять 31 строку. Молча вырезать нельзя.

### A5. Трекер не следует теме портала

`medcard_habits.js:5-6` — палитра `C`: 12 hex-литералов, замороженный снимок тёмной темы.

Светлая тема реальна и включается **автоматически**: `server.js:4002-4007` генерирует
`:root[data-theme="light"]{…}` и `@media (prefers-color-scheme: light)`. То есть
пользователю со светлой темой в ОС достаточно открыть страницу.

`habits.html` тему подключает (`:15`), страница перекрасится — а всё, что рисует JS
(полосы целей, фильтры, тексты модалок, подписи полей), останется тёмным.

Приём для починки на платформе уже отработан:
`getComputedStyle(document.documentElement).getPropertyValue('--ui-…')` —
`sb-resize.js:45`, `tbl-resize.js:60`, `sidebar.js:584`, `bottom-nav.js:90`,
`theme-toggle.js:42`. Это недоделка, не ограничение.

Соответствие полное — токен есть у каждого из 12 полей:

| поле | hex | токен | значение темы | сходится |
|---|---|---|---|---|
| `bg` | `#0a0a0a` | `--ui-bg` | #0a0a0a | да |
| `card` | `#141414` | `--ui-surface` | #141414 | да |
| `in` | `#111` | `--ui-surface-3` | #111111 | да |
| `bd` | `#262626` | `--ui-line` | #262626 | да |
| `bd2` | `#1e1e1e` | `--ui-line-2` | #1e1e1e | да |
| `tx` | `#e8e8e8` | `--ui-tx` | #e8e8e8 | да |
| `tx2` | `#8b8b8b` | `--ui-tx-2` | #8b8b8b | да |
| **`tx3`** | **`#666`** | **`--ui-tx-3`** | **#6a6a6a** | **НЕТ** |
| `br` | `#00a0ff` | `--ui-brand` | #00a0ff | да |
| `ok` | `#4ade80` | `--ui-ok` | #4ade80 | да |
| `wn` | `#fbbf24` | `--ui-warn` | #fbbf24 | да |
| `dg` | `#f87171` | `--ui-danger` | #f87171 | да |

Не предлагать `--ui-card-bg`/`--ui-card-border`: они живут только в `ui.css` и в
светлой теме не переопределяются — замена на них светлую тему не починит.

### A6. Копирование ссылки рапортует об успехе, которого не было

`medcard_habits.js:1511-1515`, `refCopyLink`:

```js
catch(e){ v.select(); document.execCommand('copy'); toast('Ссылка скопирована'); }
```

Результат `execCommand` не проверяется, тост безусловный. `v` — `readonly`-input в
модалке (`:1500`); в iOS Safari `select()` на readonly-поле часто не выделяет,
`execCommand` вернёт `false`, пользователь прочитает «Ссылка скопирована» с пустым
буфером. Канон `copy.js:60-62` возвращает `!!ok` и честно говорит
«Браузер не дал скопировать» (`:159`).

### C1. Toast — и порядок работ, который нельзя нарушать

Дублируются и CSS, и логика. Расхождения:

| | локальный `#toast` | `.plt-toast` (канон) |
|---|---|---|
| z-index | 600 (**под модалкой 1100**) | 9999 |
| длительность | 2200 мс | 3000 мс, настраивается |
| ширина | по контенту | 75vw / max 640px, перенос |
| кегль | 13px литералом | `var(--ui-toast-fs,14px)` из `/set` |
| ошибки | нет, всё зелёным | `.err` красный |
| пауза на hover | нет | есть |
| несколько плашек | вторая затирает первую | стопкой по `opts.key` |
| док мобилки | ложится на кнопки | `calc(24px + var(--cfbn-pad))` |

**Удалять фолбэк можно только вторым шагом.** `habits-sw.js:27-34` кладёт в `SHELL` при
установке только страницы, спрайт, лого и манифест — `/toast.js` там нет, он попадает в
кэш лишь через stale-while-revalidate при первом онлайн-заходе. Первый офлайн-старт PWA:
страница из кэша есть, `toast.js` нет → `pltToast` нет → и именно тогда нужно самое
важное сообщение «Нет сети — записано локально» (`medcard_habits.js:862`).

Порядок: **сначала** добавить `/toast.js`, `/copy.js`, `/loc-time.js` в `SHELL`
(`habits-sw.js:27`) с бампом `CACHE`, **потом** удалять `habits.html:42`, `:156` и ветку
`medcard_habits.js:78-79`. Наоборот — офлайн-заход молча потеряет все сообщения.

Попутно: `medcard_habits.js:878-885` уже зовёт `pltToast` напрямую с `else` на локальный
`toast()` — после миграции развилка схлопывается в две строки.
И: `refs.html:758-760` описывает этот дубль, но указывает `ms:1800`, тогда как в коде
`:79` стоит `2200` — снимок в реестре разошёлся с кодом.

### C3. Loc-time

`tshort` (`:204-206`) — посимвольная копия второй половины `utcfmt` (`:20-24`):

```
:21   const tz=LOCAL_TZ||(window.CF_REGION&&window.CF_REGION.timezone)||'Europe/Moscow';
:205  const tz=LOCAL_TZ||(window.CF_REGION&&window.CF_REGION.timezone)||'Europe/Moscow';
:23   const time=d.toLocaleTimeString('ru-RU',{hour:'2-digit',minute:'2-digit',timeZone:tz});
:206  return  d.toLocaleTimeString('ru-RU',{hour:'2-digit',minute:'2-digit',timeZone:tz});
```

Разбор UTC-строки `String(s).replace(' ','T')+'Z'` повторён **шесть раз**: `:11`, `:20`,
`:204`, `:304`, `:1127`, `:1190`. `loc-time.js:45-63` (`locDT`) делает то же надёжнее —
проверяет, нет ли зоны уже в строке (`:58`), отдельно разбирает дату без времени (`:52-56`).

Канон: `locHM`/`locTime`/`locDT` из `/loc-time.js` — подключён на 19 страницах, кэширует
`Intl.DateTimeFormat`; ADR-167 и `docs/VERSION.md:63` фиксируют его как замену копиям.

**Починка:** подключить `/loc-time.js?v=2` в `habits.html`, удалить `tfmt` и `tshort`,
вызовы → `locHM`; `:304/:1127/:1190` → `locDT`.

**Осторожно:** `utcfmt` менять на `locTime` целиком **нельзя** — форматы разные
(«12 сент. 2026, 14:32» против «12.09.2026, 14:32»), вид истории изменится. `utcfmt` —
дубль механики, но не формата; оставить сборку поверх `locDT`.

Побочно: `/tz.js` подключён (`habits.html:215`), но ни одна его функция не вызывается —
берётся только `window.CF_REGION` как запасной пояс (`:21`, `:205`). Убирать тег нельзя,
пока фолбэк в силе.

## F. Что проверено и дублем НЕ является

Не сводить, несмотря на внешнее сходство:

- **`cfToday()` (`/tz.js`) и `ymdLocal`** — разные пояса по замыслу: портал против
  устройства (`medcard_habits.js:12-18`).
- **`uiToast` (`ui-dialogs.js:148`) и `pltToast`** — два разных общих чипа платформы с
  разной позицией и семантикой; `refs.html:781-783` отмечает, что правила выбора между
  ними в коде нет. Отдельная проблема, не дубль habits.
- **`dfmt` (`:10`) и `locDate`/`locDM`** — форматы разные («7 сент.» против «07.09.2026»),
  и `dfmt` корректно обходит сдвиг через `T12:00:00`. Дублируется механика разбора, не вывод.
