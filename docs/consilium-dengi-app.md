## 1. Идея в двух словах

Оцифровать личные расходы до уровня **позиций чека**, а не только сумм из банка. Дальше:
- видеть, **что именно** покупаю (хлеб Harris, кофе, пиво), а не просто «Пятёрочка 387 ₽»;
- связать еду с **медкартой**: что ем каждый день ↔ как меняются анализы;
- **деньги в паре**: кто сколько вносит в общие траты (без показа сумм — только доля полоской);
- **общие долги с друзьями** в духе Splitwise: «кальян 1200 ₽ с Саньком 50/50», «на следующий день он заплатил за меня», «кафе 2000 ₽ с Ириной».

## 2. Что уже есть на портале

**Стек:** Node.js + Express (pm2), SQLite (better-sqlite3: `tasks.db`, `med.sqlite`), фронт — чистый HTML/JS + Chart.js,
ИИ — Anthropic Claude (Haiku 4.5 для распознавания документов) и OpenAI через шлюз, вход и уведомления через Telegram.

**Финансы (страница /cash):**
- Т-Бизнес (ИП) — автосинк по API T-Банка по крону.
- Личная карта Т-Банка — импорт CSV-выгрузки (дата, сумма, статус, категория банка, описание), дедупликация.
- Скан документа ИИ (чек, счёт, выписка, фото/PDF/xlsx) → **одна** операция: сумма, дата, контрагент. Позиции чека не сохраняются.
- Календарь факт/план, «Список», «Карты», «Итоги» по месяцам, фильтры по счетам.
- Налоги и ЖКХ: загрузка квитанций, план-строки, автосверка с выпиской.
- Счета/УПД/акты, расходы по лидам, траты в «Путешествиях» (сверка с банком).
- Таблица `cash_transactions` (date, amount, category, type fact|plan, account, counterparty, …).

**Модуль «Пара» (/pair/app):** общение и совместимость (пульс, вопросы, договор, цели, вишлист, «Моё, твоё, наше» — учёт имущества).
Плитка «Бюджет пары» помечена «Скоро».

**Медкарта:** анализы, рекомендации по показателям; раздел «Питание» уже читает **штрихкод и этикетку** продукта.

**Чего нет:** позиций чека, интеграции с ФНС, долгов «кто кому должен», связи денег с медкартой.

## 3. Как сейчас живёт процесс у пользователя

Сканирую чеки приложением ФНС → вручную заношу в личный Т-Банк → выгружаю CSV на портал.
В итоге на портале только суммы, **что купил — неизвестно**.

## 4. Техническая разведка (наш ресерч, проверьте и поправьте)

- **QR-код чека** содержит только реквизиты: `t=20260930T1650&s=387.95&fn=7384440800499914&i=200713&fp=3007407384&n=1`. Позиций в нём нет.
- **Позиции** можно получить:
  1. неофициальный мобильный API ФНС `irkkt-mobile.nalog.ru` (вход по ИНН+пароль ЛК или телефон+СМС) — бесплатно, но недокументирован, может сломаться;
  2. платный сервис **proverkacheka.com** (API по токену) — стабильнее, лимиты/цена;
  3. распознавание фото чека ИИ (у нас уже есть cashscan) — без ФНС, но с ошибками OCR;
  4. электронные чеки на e-mail / «Мои чеки онлайн» / приложения сетей (X5 Клуб).
- **Код маркировки** (теги 1162/1163) есть только у маркированных товаров (молочка, вода, пиво и др.) → EAN → **Open Food Facts** (КБЖУ; по РФ покрытие ~30–40%).
- Название позиции «ЧЕРНОГ.Нап.КОК.МОХ.л/мят 0.45л» → нормализация LLM → категория/продукт; КБЖУ — только из справочников, не выдумывать.
- GitHub: клиенты API ФНС на Python/Node (fns-receipt-parser, checkeris и др.), open-source делёжки: **Spliit** (клон Splitwise), Firefly III, Actual Budget.

**Тестовый чек (Пятёрочка, 30.09.26):** пиво ЭССА 0.4 — 99.99; соус терияки СЭН СОЙ 120 г — 79.99; основа Том Ям — 69.99;
2 × «Черноголовка» мохито 0.45 — 68.99. Итог 387.95, скидка X5 Клуб 26.

## 5. Аналоги на рынке

## 6. Вопросы консилиуму

1. **Целесообразность.** Стоит ли делать позиции чеков для личного портала, или хватит банковских категорий? Где реальная польза, где самообман?
2. **Источник позиций.** API ФНС (неофициальный) vs proverkacheka.com vs OCR фото vs e-mail-чеки — что выбрать как основной и что как запасной? Риски блокировки/юридические.
3. **Связка с банком.** Как надёжно склеить чек с операцией из CSV Т-Банка (сумма+время±, карта *6717)? Как избежать дублей?
4. **Модель данных.** Предложите таблицы: чек, позиции, продукт-справочник, связь с `cash_transactions`, участники/доли, долги. Минимум полей.
5. **Питание ↔ медкарта.** Как из позиций чеков получить хоть сколько-то честную картину потребления (купил ≠ съел; банка кофе на месяц)? Какие метрики имеют смысл для корреляции с анализами, а какие — шум?
6. **Деньги в паре.** Как показать доли без сумм (полоска «я / партнёр»)? Что считать общими тратами? Этичные подводные камни.
7. **Долги с друзьями.** Минимальный UX «добавил трату → разделил 50/50 / по позициям → отметил возврат». Нужен ли друзьям аккаунт, или хватит ссылки/Telegram-бота?
8. **MVP.** Что сделать за 1–2 недели одному разработчику с ИИ-ассистентом? Порядок этапов.
9. **Что мы упустили?** Риски, приватность, альтернативы.
